V2.0 / PREPARE YOUR IMAGE

下载什么，怎么打包。
按步骤完成第一次导入。What to download. How to package it.
Your first import, step by step.

先下载指定的原始系统包，再下载完整打包工具源码。在 Linux 中打包后，只需把生成的镜像和导入描述文件传到设备。无需编译 App、Linux 内核或 GPU 兼容库。Download the specified base-system archive and the complete packaging-tool source. Package on Linux, then transfer the resulting image and import descriptor to your device. You do not need to compile the app, Linux kernel or GPU compatibility library.

最后导入 App 的只有两个文件Only two files go into the apptoucharium-system.erofs

原始 .raw.xz 包和 GitHub 源码 ZIP 不能直接导入 Toucharium。The original .raw.xz archive and GitHub source ZIP cannot be imported directly into Toucharium.

STEP 01

下载指定的原始系统包Download the pinned base archive

当前工具固定支持 UBports Ubuntu Touch 24.04-1.x PDK，第 470 构建，ARM64。请下载下面这个完整文件，不要换成 amd64 / x86 系统包，也不要任意选择另一个构建编号。The current tool pins UBports Ubuntu Touch 24.04-1.x PDK, build 470, ARM64. Download the complete file below. Do not substitute an amd64/x86 guest archive or a different build number.

BASE SYSTEM / ARM64 / BUILD 470

ubuntu-touch-pdk-img-arm64.raw.xz

下载原始包（UBports）Download archive (UBports) ↗打开官方构建页Open official build page ↗

这是上游原始系统包，不是可以直接导入 App 的最终镜像。本网站不托管系统镜像。This is the upstream base-system archive, not the finished app-import image. This website does not host system images.

用普通浏览器下载。官方 CI 可能弹出安全验证；遇到 403 时，可在浏览器打开上面的构建页并完成验证。若该历史产物已经不可获取，请查看项目说明或反馈，不要用不匹配的文件绕过校验。Use a normal browser to download it. The official CI may show a browser security challenge. If you see a 403 response, open the build page in your browser and complete its verification. If the historical artifact is no longer available, consult the project or report it rather than bypassing validation with another file.

在 Linux 上下载时，把文件放到当前用户主目录，保留原文件名。若文件在 Mac 的 Downloads 中，按下一步的虚拟机示例传入 Linux。打包工具会再次自动校验此值。When downloading on Linux, place the file in your current user’s home directory and retain its filename. If it is in Downloads on a Mac, use the VM example in the next step to transfer it into Linux. The packaging tool verifies this digest again automatically.

STEP 02

准备 Linux 打包环境Prepare the Linux environment

打包必须在有 sudo 权限的 ARM64 或 x86-64 Linux 中运行。可使用 Ubuntu 22.04 / 24.04。Mac 需要 Linux 虚拟机；iPhone 和 iPad 只负责导入最终文件。两种 Linux 主机架构都会生成供 Toucharium 使用的 ARM64 镜像。Packaging runs on ARM64 or x86-64 Linux with sudo access; Ubuntu 22.04 / 24.04 can be used. A Mac needs a Linux VM. iPhone and iPad only import the finished files. Either Linux host architecture produces an ARM64 guest image for Toucharium.

首次建议预留 至少 50 GB 空闲磁盘空间，原始磁盘解压后约 25 GB。工作目录放在 Linux 本地文件系统中，需支持 loop 挂载和 OverlayFS，不要放到 macOS 共享文件夹。Allow at least 50 GB of free disk space for a first run; the decompressed raw disk is approximately 25 GB. Keep the work directory on a local Linux filesystem supporting loop mounts and OverlayFS, rather than a macOS shared folder.

Mac 用户：使用 Multipass 的完整起步示例On a Mac: a Multipass setup example

先按 Multipass 官方说明安装 Multipass。以下示例创建 Ubuntu 24.04 虚拟机，分配 70 GB 磁盘和 4 GB 内存。若同名虚拟机已存在，可使用现有虚拟机或换一个名称。Install Multipass using the official instructions. This example creates an Ubuntu 24.04 VM with a 70 GB disk and 4 GB of memory. If that name already exists, use your existing VM or choose another name.

Mac 终端 · 尚未进入 LinuxMac terminal · before entering Linux
multipass launch 24.04 --name toucharium-packager --disk 70G --memory 4G --cpus 4
multipass transfer "$HOME/Downloads/ubuntu-touch-pdk-img-arm64.raw.xz" toucharium-packager:.
multipass shell toucharium-packager

执行 shell 命令后，后续的 Linux 命令都在虚拟机内运行。这里的 $HOME 指 Linux 用户主目录，不是 Mac 主目录。参考：创建虚拟机、传输文件。After entering the shell, run subsequent Linux commands inside the VM. $HOME now refers to your Linux home, not your Mac home. References: launch and transfer.

在 Linux 内安装打包依赖：Install the packaging dependencies inside Linux:

Linux 终端 · 虚拟机内或 Linux 主机Linux terminal · VM or Linux host
sudo apt update
sudo apt install -y git python3 erofs-utils util-linux mount xz-utils

不需要安装 Xcode、C++ 编译器、CMake 或 Ninja。GPU 兼容库已由打包工具内置，工具会验证后使用。Xcode, a C++ compiler, CMake and Ninja are not required. The tool already embeds the GPU compatibility library and verifies it before use.

STEP 03

下载完整打包工具源码Get the complete packaging tools

需要的是 toucharium-v2.0 分支的完整项目源码，不要只下载 package.py 单文件。它还会调用同目录的其他脚本和配置。Use the complete project source from the toucharium-v2.0 branch, not package.py alone. It needs the other scripts and configuration files beside it.

Linux 终端 · 下载源码并进入项目根目录Linux terminal · get the source and enter its root
cd "$HOME"
git clone --depth 1 --single-branch --branch toucharium-v2.0 https://github.com/kobewang126/Kernarium.git toucharium-tools
cd toucharium-tools

也可以下载源码 ZIP，完整解压后进入包含 tools/ 的项目根目录，再执行下一步。ZIP 是打包工具源码，不是原始系统包。Alternatively, download the source ZIP, extract the complete archive and enter the project root containing tools/ before continuing. This ZIP contains the packaging-tool source, not the base-system archive.

STEP 04

运行打包命令Package the image

确认原始 .raw.xz 文件位于 Linux 用户主目录，并且当前目录是 toucharium-tools。然后复制执行：Make sure the .raw.xz archive is in your Linux home directory and that you are in toucharium-tools. Then run:

Linux 终端 · 在项目根目录执行Linux terminal · run from the project root
mkdir -p "$HOME/toucharium-output"
sudo python3 tools/rootfs/ubuntu-touch/package.py \
  --archive "$HOME/ubuntu-touch-pdk-img-arm64.raw.xz" \
  --work "$HOME/toucharium-work" \
  --output "$HOME/toucharium-output/toucharium-system.erofs"

如果文件不在示例位置，修改 --archive 后的路径。--work 是 Linux 本地缓存与工作目录；--output 是一个尚不存在的输出文件。工具会校验原始包、解压、应用适配并生成 EROFS 与配套 JSON，不会自动下载系统镜像或修改你的原始包。If the archive is elsewhere, adjust the path after --archive. --work is a local Linux cache/work directory, and --output must be a new output filename. The tool verifies and decompresses the input, applies adaptations and writes EROFS and JSON outputs. It does not download a system image or modify the original archive.

等待命令成功结束，最后应看到 Image、Producer receipt 和 Import descriptor 三项输出。不要只看到中间的进度就关闭终端。输出已存在时请换一个新名称，不要直接覆盖。Wait for the command to finish successfully. Its final output lists Image, Producer receipt and Import descriptor. Do not close the terminal after an intermediate progress message. If the output already exists, choose another filename rather than overwriting it.

传输两个结果文件并导入Transfer and import the two result files

结果在 Linux 的 $HOME/toucharium-output/ 中。三个文件用途不同：The output is in $HOME/toucharium-output/ inside Linux. The three files have different roles:

文件File用途Use
toucharium-system.erofs传到 iPhone / iPadTransfer to iPhone / iPad
最终系统镜像The finished system image
toucharium-system.erofs.import.json传到 iPhone / iPadTransfer to iPhone / iPad
与镜像配套的导入描述文件The matching import descriptor
toucharium-system.erofs.json打包记录，留在电脑即可，不需要在 App 中选择。Producer receipt. Keep on your computer; do not select it in the app.
使用 Multipass：把结果取回 MacWith Multipass: copy the results back to your Mac

先在 Linux shell 输入 exit，回到 Mac 宿主机终端，再执行下面两条命令。First enter exit in the Linux shell to return to your Mac terminal, then run both commands below.

Mac 终端 · 已退出 Linux shellMac terminal · after leaving the Linux shell
multipass transfer toucharium-packager:toucharium-output/toucharium-system.erofs "$HOME/Downloads/"
multipass transfer toucharium-packager:toucharium-output/toucharium-system.erofs.import.json "$HOME/Downloads/"
  1. 把 .erofs 和 .erofs.import.json 两个文件同时 AirDrop 到设备，保存到“文件”App 的同一个文件夹。AirDrop both the .erofs and .erofs.import.json files to your device and save them in the same folder in Files.
  2. 打开 Toucharium → Import system image。在文件选择器中同时选中这两个文件；必要时先打开“选择”模式。Open Toucharium → Import system image. Select both files together in the document picker; enable Select mode if needed.
  3. 保持 App 在前台，等待复制与校验。成功导入一次后，后续无需重复导入。iPhone 和 iPad 可以使用同一份镜像及配套 JSON。Keep the app foregrounded while copying and verification finish. A successful import is reused on later launches. The same image and matching JSON work on iPhone and iPad.

确认正常启动后，可删除设备“文件”App 中的外部原文件以节省空间。请勿删除 Toucharium 应用目录内的已安装镜像或数据文件。Once normal startup is confirmed, you may delete the external originals from Files to save space. Do not delete the installed image or data files inside Toucharium’s app directory.

TROUBLESHOOTING

遇到问题，先检查这里。If something fails, check these first.

原始包 SHA-256 不匹配The base archive SHA-256 does not match

确认下载的是第 470 构建的 ARM64 .raw.xz 完整文件，不是网页、源码 ZIP 或其他构建。若下载返回了 403 页面，保存下来的可能是 HTML，而不是镜像。不要跳过校验。Check that you have the complete ARM64 .raw.xz from build 470, not a web page, source ZIP or another build. A 403 download may have saved HTML instead of the archive. Do not bypass verification.

出现 Operation not permitted / 挂载失败Operation not permitted or mount failure

确认使用 sudo，并在支持挂载的完整 Linux 主机或虚拟机中运行。受限容器可能没有挂载权限；工作目录也不能放到 Mac 共享文件夹。Use sudo on a full Linux host or VM with mount support. Restricted containers may not have mount permissions. Keep the work directory off Mac shared folders.

App 提示选择的文件不匹配The app says the files do not match

只选同次打包生成的 .erofs 和 .erofs.import.json。不要选 .erofs.json 打包记录，也不要修改 JSON 中的校验值。重新打包的镜像可能有不同 SHA，必须使用新生成的配套 JSON。Select the .erofs and .erofs.import.json from the same packaging run. Do not choose the .erofs.json producer receipt or edit its checksums. A rebuilt image can have a different digest and needs its own generated descriptor.

下载后只有 .raw，没有 .raw.xz？The browser left a .raw file instead of .raw.xz?

有些浏览器会自动解压下载内容。原本不需要手动解压；若现在已有完整的 .raw 文件，可以把打包命令中的 --archive 改为 --disk，并将路径改成该 .raw 文件的位置，其他参数保持不变。传入 Linux 时也使用实际文件名。工具仍会校验解压磁盘的大小和 SHA-256。Some browsers automatically decompress downloads. Manual extraction is unnecessary, but if you already have the complete .raw disk, replace --archive with --disk and point it to that .raw file; keep the other options unchanged. Transfer the actual filename into Linux too. The tool still checks the raw disk size and SHA-256.

Mac 上能不能直接运行打包命令？Can I package directly on macOS?

不能直接打包；需要 Linux 的挂载与文件系统能力。可以在 Mac 下载文件，再传入 Linux 虚拟机完成打包。Packaging needs Linux mount and filesystem facilities. Download files on your Mac if you prefer, then transfer them into a Linux VM to package.
